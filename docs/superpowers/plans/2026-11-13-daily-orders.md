# 计划 5：每日出单和纸面跟单

**目标**：每个调仓日收盘后，用当天及以前的数据，算出下一个交易日要卖什么、买什么（只数、股数、参考价、预计金额），附安全检查。纸面跟单按这份清单记账。

**依据**：`docs/DECISIONS.md` 2026-11-13「实盘和纸面跟单的停止规则」。用户同意"开始"（2026-11-13）。

## 关键设计

- **只有一份规则**：买卖逻辑必须和回测的账户引擎 `qt/account.run_account` 完全一致。出单函数 `qt/live/orders.plan_orders` 单独写成纯函数（输入：当天打分、能买能卖、行业、现有持仓市值、现金、成交价、持股只数上限；输出：卖单、买单），再用**回放测试**锁死一致性：在随机生成的行情上跑回测，每天把回测账户的状态喂给出单函数，产出的买卖必须和回测当天的成交一模一样。以后谁改了账户引擎而没改出单函数，这个测试会失败
- 回测的约定是 T 日收盘出信号、T+1 收盘成交，手数按 T+1 价格算。实盘出单时还不知道 T+1 的价格，用 T 日收盘价算股数和金额（参考价），这是唯一的差别；回放测试里喂 T+1 价格，要求完全一致
- 只支持现行基线用到的规则：排名卖出、仓位上限（多余的按排名从低到高卖）、单股和行业上限、最小交易额、每只预算上限。用到止损、回撤兜底、回撤分档、事件点名卖出的规则，出单函数直接报错，不默默算错
- 调仓日历：从跟单开始那天起每 20 个交易日一次；估值 + 趋势的持股只数上限从同一天起每 20 天更新（和回测一样）

## 任务

1. **`qt/live/orders.py`：`plan_orders`**（先写测试）
   - 回放测试：随机行情（含停牌、不能买、不能卖、行业上限、持股只数上限变化、科创板），回测每天的成交 = 出单函数的输出
   - 单元测试：非调仓日只按仓位上限卖、不买；现金不够时最后一只减手；不支持的规则报错
2. **安全检查和清单输出**：`check_orders` —— 买入总额不超过现金加卖出所得、每笔整手、持股只数不超过上限、没有同时买卖同一只、数据日期是预期的信号日；输出 CSV 和一页 Markdown
3. **`scripts/live_orders.py`**：给定信号日和账户状态文件（现金、持仓股数、买入日），读数据、算打分、出清单。先只在开发段的日期上运行；核对：取回测里某个调仓日的账户状态，脚本给出的清单和回测下一天的成交一致（价格差异除外）
4. **（要用户先决定）最新数据**：每天更新行情和财务数据、算最近的因子。要读封存段，等用户在 DECISIONS 里那个未决问题上选 (a) 或 (b)
5. **（之后）纸面账户**：按清单在 T+1 收盘价成交记账、每天记净值、按停止规则①②检查

任务 1–3 不读封存段。
