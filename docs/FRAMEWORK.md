# 研究框架（第 2 版，2026-11-12 起）

这是这个代码库的规程文件：研究怎么一圈一圈往前走、什么算证据、什么时候停。它取代此前"每个计划各定一套规则"的做法。为什么这样改，见 [`research/2026-11-12-literature-review.md`](research/2026-11-12-literature-review.md)。

用户 2026-11-12 把研究决策和代码库交给我负责。这份文件里的规则都是我定的，用户可以改。**框架版本：2.0。**

## 0. 这个代码库是做什么的

它是一个**研究实验室**，产出只有两种，都要有据可查：

1. 一个冻结的、可以每天出单的选股流程，通过了事先写死的检验；或者
2. 一个诚实的结论："在现有数据和约束下，选股跑不赢指数，买指数基金。"

好看的回测不是产出。第 2 种结论和第 1 种同样算完成任务。

## 1. 不变的约束

- 用户的四条：账户 10 万元现金；符合 A 股交易规则；只做多；不融资融券（以及原有的：全 A 主板、不碰测试段）
- 测试段（2022-01-01 起）封存：取数都经过 `qt/config.check_range()`；最终测试要用户批准，`QT_UNLOCK_TEST=1`，一个世代只跑一次
- 任何规则先写下来、提交，再运行

## 2. 数据分三层

| 层 | 区间 | 用途 |
|---|---|---|
| 开发段 | 2010-01 ~ 2021-12 | 全部研究在这里做。原来的"训练段 + 验证段"合并：验证段已经看过四次，不再是独立证据 |
| 封存段 | 2022-01 ~ 数据末尾 | 唯一干净的数据。一个世代用一次；用过之后它就只能当体检，不能再当检验 |
| 实盘前推 | 封存段用完之后 | 真正新鲜的证据只有这个（纸面跟单，再小资金） |

开发段分三个**制度阶段**，所有结果都分段报告：

| 阶段 | 区间 | 特点 |
|---|---|---|
| 一 | 2010–2014 | 壳价值高，退市基本是名义上的 |
| 二 | 2015–2018 | 股灾；2016-09 借壳收紧、2017 年发行提速，壳价值开始下降 |
| 三 | 2019–2021 | 注册制试点、退市变真、机构化。**和今天最像，权重最大** |

## 3. 研究对象是"流程"，不是"因子名单"

一个**流程**（`qt/lab/procedure.py` 的 `Procedure`）写明从候选因子到每天持仓的每一步：用哪些因子族、怎么合成、哪些股票不买、买几只、多久调一次、什么情况卖。流程里如果有任何一步要用数据来定（比如选因子），这一步必须能逐年只用过去的数据重做——被检验的是"这套定法"，不是定出来的结果。

任何时候有且只有一个**基线流程**。每一圈研究只做一件事：提出对基线的一处改动，用固定的规则判断要不要采纳。

## 4. 一圈研究怎么走

1. **读状态**：`lab/BELIEFS.md`（目前相信什么、依据多强）、`lab/cards/`（做过哪些假设、结果）、`lab/runs.jsonl`
2. **写假设卡** `lab/cards/Hnnn.yaml`，字段见下。**提交之后才能跑**——程序会检查卡片已经提交、且提交后没被改过
3. **便宜的证据**（不跑账户）：分阶段看横截面证据、最顶端各档的收益、大亏只数。这一步不计试验次数，但看了什么要写进卡片
4. **账户检验**：`python scripts/lab_run.py Hnnn`。候选流程和基线在开发段上各跑四个错开的调仓起点，配对比较。每张卡最多 6 次
5. **裁决**：由 `qt/lab/gates.py` 按第 6 节的规则算出"采纳 / 不采纳"，不由我判断。采纳就更新基线
6. **记录**：结果写回卡片和 `lab/runs.jsonl`；每次账户检验记一条试验日志。程序错误让某次运行无效时：在 `lab/runs.jsonl` 追加作废记录、写明原因，报告开头标"作废"；作废的不占预算，编号不复用
7. **更新认识**：改 `lab/BELIEFS.md`——这一圈让哪条认识变强、变弱或被推翻
8. 同一方向连续两张卡不采纳，这个方向冷却（本世代不再提）；同一方向最多三张卡

### 假设卡的字段

| 字段 | 内容 |
|---|---|
| `id`、`parent` | 编号；它建立在哪张卡之上 |
| `family` | 方向（用于冷却计数），如"问题股排除""持仓结构""因子族" |
| `kind` | `收益型` 或 `防雷型`（决定用哪套采纳规则） |
| `mechanism` | 为什么会有效，谁在对面亏钱，为什么会持续。**依据只许引用 2021 年底以前的机制和文献** |
| `change` | 对基线的**一处**改动 |
| `prediction` | 事先预期：哪个指标、往哪个方向、大概多少 |
| `falsification` | 什么结果算被推翻 |
| `variant` | 改动的程序化写法（对 `Procedure` 的字段覆盖） |
| `seen_before` | 写这张卡之前已经看过哪些相关结果（如实写） |

## 5. 评价口径（一个世代内冻结）

实现在 `qt/lab/`，一个世代内不改；要改就升框架版本，旧结论不追溯。

- **账户**：`qt.account.run_account`，10 万元、100 股一手、最低 5 元佣金、涨跌停、T 日信号 T+1 收盘成交
- **四个调仓起点**：错开 0、5、10、15 个交易日各跑一次，报平均，也报最差
- **基准**：能持有等权（每 20 个交易日在能买的股票里等权买入并持有，和账户同一段日期、同一个起点）；沪深300 全收益
- **成绩单**（`qt/lab/scorecard.py`）：分三个阶段和全段报——扣成本后年化、相对能持有等权的超额、最大回撤、换手、成本；**大亏只数**（平仓时亏损超过 40% 的持仓笔数）；最差五笔占期初资金的比例
- **最顶端曲线**（`qt/lab/evidence.py`）：按打分取前 15、50、150 名和最好的五分之一，持有 20 天、不扣成本，分阶段看是不是越靠前越好；前 15 名里 20 天跌超 20% 的只数和随机挑的比
- **配对比较**：候选减基线的每日收益差（四个起点平均），报年化差值、Newey-West t 值（滞后 20 天）、分阶段差值

## 6. 采纳规则（固定，算出来）

**收益型**（目的是多赚）——全部满足才采纳：
1. 配对差值的 t 值 ≥ 2.0
2. 阶段三的差值 > 0，且阶段一、二里至少一个 > 0
3. 成本翻倍后，全段差值仍 > 0
4. 大亏只数没有明显变多：不比基线多出一成以上，至少容许多 1 笔（2026-11-13 在任何真实数据运行之前从"不比基线多"放宽：几笔大亏的偶然性很大，假数据测试里一个明显更好的改动因为多 1 笔被否掉）
5. 卡片里预期的方向成立

**防雷型**（目的是少踩雷）——全部满足才采纳：
1. 阶段三的大亏只数比基线少至少 30%
2. 阶段三的差值 > 0
3. 全段配对差值的 t 值 > −1.0（没有明显变差）
4. 卡片里预期的方向成立

说明：阶段一、二里"垃圾股也涨"的那部分收益来自已经消失的制度，防雷型改动允许在那两段少赚；但全段不能明显变差。

**单项比较不能用来选参数**：两个相关的方案，12 年里夏普差不到 0.4 分不出来。持股数、调仓间隔这类参数按事先的理由定，敏感性只报告。

## 7. 预算和记账

- 一张卡最多 6 次账户检验；一个世代最多 12 张卡
- 试验次数**累计、永不清零**（含以前的 3700 多次）。每份成绩单同时给出"这么多次试验、12 年数据，纯噪声里最好的夏普期望是多少"（`qt/lab/protocol.noise_sharpe`）
- 12 张卡用完：要么进第 8 节，要么得出第 0 节的第 2 种结论。不许追加

## 8. 什么时候可以用封存段

同时满足才行：

1. 基线流程冻结（参数、代码提交号写进 `DECISIONS.md`）
2. 在开发段上：四个起点平均的扣成本后年化，在三个阶段里都高于能持有等权和沪深300 全收益；四个起点各自全段都高于能持有等权；成本翻倍后全段仍高于两个基准
3. 事先列好的邻近参数（持股数、调仓间隔、卖出名次各上下一档）全段都高于能持有等权
4. 一次独立复查（另开一个不带我思路的检查，只看卡片、代码和结果）没有未解决的问题：前视、数据对齐、成本、重复
5. 用户批准

**通过 = 封存段扣成本后年化高于沪深300 全收益，也高于能持有等权**（2026-11-12 已登记，不改）。最大回撤、成本翻倍、分年、DSR 只报告。

封存段一个世代只用一次。不通过：这个世代结束，结论写第 0 节第 2 种，或者开新世代——但新世代不能再把这段数据当检验。

## 9. 防偷看未来

三层，各管各的：

- **数据层**：`check_range()`；财务数据按公告日对齐
- **代码层**：时间因果测试（`tests/test_lab_causality.py`）——把某一天之后的数据全改掉，这一天及以前的信号必须一个数都不变
- **知识层**：我本身知道 2022 年以后的行情，提假设时可能不自觉偏向后来表现好的东西，这靠自我提醒消不掉。办法：假设的依据只许引用 2021 年底以前的机制和文献；调研时不采集 2022 年以后的因子收益；通过标准事先写死；封存段的结果同时也是对"我有没有被记忆带偏"的一次检验，这一点提前承认

## 10. 已知的失效模式（每条都有自动检查）

| 编号 | 失效模式 | 出处 | 自动检查 |
|---|---|---|---|
| F1 | 规则贴着某一次历史事件 | 计划 4 | 成绩单分三个阶段报；采纳规则要求不止一个阶段成立 |
| F2 | 挑选次数太多 | 计划 3c | 每张卡、每个世代的次数上限由程序拦；累计次数进成绩单 |
| F3 | "选"这一步没有被样本外检验 | 计划 3d | 流程里用数据定的步骤必须走逐年重做的接口（`Procedure.fit`） |
| F4 | 只看整体预测力，不看最顶端 | 计划 3d | 成绩单必报最顶端曲线和大亏只数 |
| F5 | 看过结果再改规则 | 计划 4 | 假设卡必须已提交且未改动，程序才肯跑 |
| F6 | 单一路径的运气 | 计划 3d | 四个调仓起点一起跑，报最差 |
| F7 | 用了未来的数据 | 通用 | 时间因果测试 |
| F8 | 基准本身有毛病 | 2026-11-10 | 基准只用 `holdable_benchmark`；旧的每日等权基准不再进任何判定 |
| F9 | 中间结果把两个不同的方案混成了同一个 | H001 第 1 次运行（2026-11-13） | 测试逐个改流程的字段，凡改变合成分的都必须在缓存钥匙里；候选和基线结果完全一样时要怀疑程序 |
| F10 | 看了结果再换判定标准（同一个改动被一类规则否决后，换成另一类再提） | H004（2026-11-13） | 同一个基线上，改动和某张被否决的卡相同（不论写法和类型）的卡，程序拒绝运行 |

**每次失败都要复盘**：哪条检查本该拦住却没拦？缺检查才新增，而且必须写成能自动执行的；常驻不超过 10 条，新增一条就合并或删掉一条。改采纳规则或评价口径 = 升框架版本，并记为一次额外的"试验"。

## 11. 代码怎么分层

| 层 | 模块 | 状态 |
|---|---|---|
| 数据 | `qt/config`、`data`、`panel`、`full_a`、`fundamentals`、`external`、`universe`、`limits` | 稳定 |
| 因子 | `qt/library`、`factor_funcs`、`formula`、`ops` | 稳定 |
| 账户引擎 | `qt/account`、`costs` | 稳定；评价口径的一部分 |
| 评价零件 | `qt/wide_eval`、`diagnostics`、`composite`、`trials`、`pbo` | 稳定 |
| **实验室** | `qt/lab/`（protocol、store、procedure、scorecard、evidence、gates、cards）、`scripts/lab_*.py`、`lab/` | 现行，新工作都在这里 |
| 已结束的计划 | `qt/plan3d`、`walkforward`、`fastsim`、`drawdown`、`position_control`、`baseline_wide` 及对应脚本 | 留作记录，不再发展 |
| 沪深300 阶段 | `qt/evaluate`、`combine`、`simulate`、`backtest`、`pipeline`、`report`、`neutralize`、`preprocess`、`factors` 及对应脚本 | 留作记录 |

`lab/` 目录（进仓库）：`cards/`（假设卡）、`runs.jsonl`（每次账户检验一条）、`BELIEFS.md`（认识表）、`reports/`（每张卡的成绩单）。
